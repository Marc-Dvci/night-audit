# Design: Ghosts, the access review that reconciles people

## 1. Overview

`apps/ghosts/` is the second application on the Night Audit skeleton. It reconciles staff access for Hollow Pines
Credit Union, a demo company of 180 current staff, and produces an access review sheet that an IT manager hands to
an auditor. Nothing under `skeleton/` changes (Req 7.1). The app supplies:

- a control file that declares the three ledgers, the normaliser chain, the grace window, the region names and the
  words of the page (Req 1.1, 7.2),
- four read-only connectors (`HrRoster`, `IdentityExport`, `SeatAssignments`, `GitHubMembers`) that subclass
  `nightaudit.connectors.Connector` and are referenced from the control with `type: python` (Req 2, 3, 4),
- an enricher, `people_context`, that adds the HR facts and the per-person summaries a reviewer reads (Req 2.2, 5.1),
- a seat summary summariser that adds run notes (Req 4.3),
- the review campaign: export, import, verify (Req 5),
- a seeded generator for the demo company (Req 6),
- a recorded demo for the shared page (Req 7.2).

| Ledger | Question | Hollow Pines source | Key |
|---|---|---|---|
| intended | Who should have access on the run date? | HR roster CSV | work email |
| observed | Which accounts are active? | Identity export CSV (and, in the GitHub variant, organisation members) | email |
| billed | Which seats do we pay for? | Per-vendor licence assignments and invoices | email; unnamed seats are unkeyed |

## 3. The control file (Req 1.1, 7.2)

`controls/staff-access.yaml`:

- `grace_hours: 72`.
- `alias_domains: {hollowpines.org: hollowpines.com}`.
- Every ledger has `normalisers: [email_canonical]`. The skeleton's `email_canonical` strips, lower-cases, removes the
  `+tag` and maps the alias domain, so `R.Voss+old@hollowpines.org` and `r.voss@hollowpines.com` are one key.
- `regions` names every code: `OB` Ghost, `O` Poltergeist, `B` Phantom seat, `I` Unprovisioned joiner, `IB` Wraith,
  `IO` Unlicensed user, `IOB` Living. Each meaning is a condition, never an accusation (audit rule 8).
- `ui`: title Ghosts; noun person / people; ledger labels HR roster, Accounts, Paid seats; columns Person (`key`),
  Region (`name`), Systems (`context:systems`), Seats (`context:seats`), Left on (`context:left_on`), Last sign-in
  (`context:last_sign_in`), Manager (`context:manager`); a headline per finding region.
- One enricher, `ghosts.context:people_context`, for regions `OB, O, B, I, IB, IO`.

`controls/staff-access-github.yaml` is the same file with one more observed source, `ghosts.github:GitHubMembers`.

The columns read `context:` rather than `attr:` because the UI kit's `attr:` shows the first record that has the
attribute, while a person can hold several accounts and several seats. The enricher joins them.

## 4. Connectors

All connectors declare `read_only = True`, read local files or make HTTP GET requests only, and raise on malformed
input. A raise makes the ledger missing and the run incomplete, so a damaged export never produces findings (skeleton
Req 9.4).

Each connector accepts the skeleton's constructor keywords (`ledger`, `key_field`, `base_dir`) and its own options.
Relative paths resolve against `base_dir`, the control file's directory.

### 4.1 HrRoster (intended, Req 2)

Reads `hr_roster.csv`: `employee_id, email, given_name, family_name, department, title, manager_email,
employment_type, location, start_date, leaving_date, github_login`.

The run date is the UTC date of the run's time, which the skeleton gives every connector before `fetch()` (skeleton Req 10.1), so `nightaudit run --at` moves it. Outside a run it is the UTC date of an injected clock.

`belongs_on(start, leaving, today)` is a pure function:

| Condition | Belongs in intended |
|---|---|
| `start_date` empty or `start_date <= today`, and `leaving_date` empty or `leaving_date > today` | yes |
| `start_date > today` (a joiner who has not started) | no |
| `leaving_date <= today` (left, including leaving today) | no |

A person who belongs is emitted with `raw_key = email` and attributes `name, department, title, manager,
employment_type, location, start_date` and, when present, `leaving_date`. A person who does not belong is not emitted
(Req 2.2); their leaving date reaches the evidence through the enricher (§5). A date that does not parse raises.

### 4.2 IdentityExport (observed, Req 3.1)

Reads `identity_export.csv`: `account_id, email, display_name, status, created, last_sign_in`. Only rows whose
`status` is `active` (case-insensitive) are emitted. Each record has `raw_key = email`, `timestamp = created` (the
account's creation time, so a new account with no seat is pending during the grace window) and attributes
`system` (the `system` option, "Hollow Pines directory"), `status`, `last_sign_in`, `display_name`.

### 4.3 SeatAssignments (billed, Req 4)

One source per vendor, with options `vendor`, `assignments` and `invoice`.

- `assignments`: `seat_id, email, assigned_on`.
- `invoice`: `invoice_id, vendor, period, seat_quantity, unit_price, currency`. The connector uses the invoice with the
  latest `period` for the vendor; a vendor name that differs from the option raises.

Let `a` be the number of assignment rows and `q` the invoice quantity.

- One keyed record per assignment, `amount = unit_price` (Req 4.1).
- When `q > a`, `q - a` records with `raw_key = ""` and `amount = unit_price` (Req 4.2). The skeleton reports them as
  unkeyed billed rows and keeps their money in `billed_unkeyed`, so amount conservation holds.
- When `q < a`, every assignment is still emitted, and the shortfall is reported by the seat summary (§6, Req 4.3).

Every record carries `vendor, invoice_id, period, invoice_seats, assigned_seats, unit_price` so the seat summary can be
rebuilt from the evidence pack alone. Row ids are `<vendor-slug>:<seat_id>` and `<vendor-slug>:unnamed-<n>`.

### 4.4 GitHubMembers (observed, Req 3.2)

Lists `GET https://api.github.com/orgs/{org}/members?per_page=100`, following `Link: <...>; rel="next"`.

- HTTP goes through an injected `HttpClient` whose only method is `get(url, headers)`. The default `UrllibClient` uses
  `urllib.request` with a timeout. There is no method for any other verb.
- The token is read from the environment variable named by `token_env` (default `GITHUB_TOKEN`), never from the
  control. A fine-grained token with organisation "Members: read" is the documented setup.
- If the response carries `X-OAuth-Scopes` (classic tokens) and any scope is outside `read:org`, `read:user`,
  `user:email`, the connector raises: the token is not read-only.
- `org` must be a valid organisation name, so a placeholder fails before any request. A `next` link to another host
  raises, so the token never leaves `api.github.com`.
- Each login maps to an email through the roster's `github_login` column (case-insensitive). An unmapped login is keyed
  `github:<login>`, which `email_canonical` leaves as is, so an organisation member nobody on the roster maps to
  becomes a visible Poltergeist instead of an unkeyed row.
- Attributes: `system` ("GitHub <org>"), `status` ("member"), `login`. GitHub does not report a membership date, so the
  record has no timestamp.

It is tested against a recorded fixture of GitHub's documented response shape and is not in the Hollow Pines control.

## 5. The people_context enricher (Req 2.2, 5.1)

`people_context(findings, options) -> dict[key, dict[str, str]]`. It reads the roster named by `options["roster"]` and
returns context for each finding. It never changes a region: the skeleton only merges its strings into
`finding.context`, and the context is part of each finding's evidence row.

The skeleton calls enrichers without the control's directory. A relative `roster` path therefore resolves against
`apps/ghosts/controls/`, where the shipped controls live; tests pass absolute paths. The enricher also needs the
control's alias domains to normalise roster emails, so the control repeats them in the enricher options, and a test
asserts the two are equal.

| Context | Value |
|---|---|
| `person` | the roster name, or none |
| `department`, `manager`, `employment_type` | from the roster |
| `left_on` | the roster leaving date when the key has no intended record (the person has left) |
| `leaving_on` | the roster leaving date when the key is still intended (a future leaver) |
| `starts_on` | the roster start date when the key has no intended record and has not left (a future joiner) |
| `hr_roster` | `no record` when the key is not on the roster |
| `systems` | sorted, distinct `system` attributes of the key's observed records, joined with ", " |
| `seats` | sorted, distinct `vendor` attributes of the key's billed records, joined with ", " |
| `last_sign_in` | the latest `last_sign_in` attribute of the key's observed records |

The enricher decides "left" from ledger membership, not from a date, so it needs no run date.

## 6. Seat summary (Req 4.3)

The seat summary is a list of run notes, made by the control's summariser `ghosts.seats:seat_notes` (skeleton
Req 10.2). It is computed only from the billed records of the run, whose attributes carry the invoice and assignment
counts and the two gaps (`unnamed_seats`, `short_seats`), so every number a note cites is on a billed record. For the
demo: "Lantern Chat invoices 3 more seats than it assigns (178 invoiced, 175 assigned)." A vendor whose invoice is
below its assignments gets "<vendor> assigns N more seats than its invoice pays for (...)". The notes are evidence
rows, shown under the headline and printed by `python -m ghosts.run`.

## 7. Review campaign (Req 5)

`python -m ghosts.review export <run>`, `import <run> <sheet.csv> --reviewer "<name>"`, `verify <run>`. `<run>` is a
run directory or a run id under `--runs` (default `runs`).

### 7.1 Export (Req 5.1)

One line per finding (`informational` false), ordered by region then key, with the columns `person, region,
region_code, systems, seats, left_on, last_sign_in, manager, decision, decision_date, run_id, evidence_chain_hash`.
`left_on` is the context `left_on` or `leaving_on`. Decision and date are empty.

- `review.csv`: a cell that starts with `=`, `+`, `-`, `@`, tab or carriage return is prefixed with `'` so a
  spreadsheet shows it as text. Import removes exactly that prefix.
- `review.html`: a self-contained page. Every value passes through `html.escape(..., quote=True)`. The page carries a
  Content-Security-Policy meta tag that allows only its own style block, by hash.

### 7.2 Import (Req 5.2)

Every row of the sheet is validated before anything is written. The import refuses the whole sheet, with a message
naming each bad row, when:

- the person is not a key the run reported as a finding ("j.doe@... was not reported by run <id>"),
- the region code differs from the run's,
- the row's run id or evidence chain hash is not this run's,
- the decision is not one of `keep`, `revoke`, `investigate`, or the date is not an ISO date,
- the same person appears twice in the sheet,
- the reviewer name is empty.

Rows with an empty decision are skipped. Accepted decisions are appended to `runs/<run_id>/evidence/decisions.jsonl`,
inside the evidence pack directory beside `evidence.jsonl`:

```json
{"index": 0, "prev_hash": "<run's final evidence chain hash>", "type": "decision", "run_id": "...",
 "evidence_chain_hash": "...", "key": "...", "region_code": "OB", "decision": "revoke",
 "decision_date": "2026-11-05", "reviewer": "...", "imported_at": "...", "sheet_sha256": "...", "row_hash": "..."}
```

`row_hash = SHA-256(prev_hash + canonical_json(row without row_hash))`, with the skeleton's `canonical_json`. The first
row's `prev_hash` is the run's final evidence chain hash, so each decision is bound to the exact evidence it was made
on. A later import continues the chain. `imported_at` comes from an injected clock.

### 7.3 Verify

`verify` checks the evidence pack with the skeleton's `verify_evidence_pack`, then the decision chain: every row hash,
every link, the seed equal to the manifest's final chain hash, and every key and region code among the run's findings.
It prints `OK` or `FAIL` with the first failing row and exits non-zero on failure.

## 8. Generator (Req 6)

`python -m ghosts.generate [--seed N] [--out apps/ghosts/data] [--healthy]`. `build_company(seed, plant=True)` returns
`{relative path: bytes}`; `write_company` writes them. It uses `random.Random(seed)`, never the clock, writes CSV with
`\n` line endings and UTF-8, and depends only on the standard library.

- 180 people belong on 2026-11-04 across eleven departments of a credit union (Executive, Member Services, Branch
  Operations, Lending, Card Services, Collections, Finance, Risk and Compliance, IT, Marketing, People). Each
  department has a head who reports to the chief executive, and larger departments have team leads.
- Names come from fixed pools of common given and family names, and branch names from a fixed list. Emails are
  `<initial>.<surname>@hollowpines.com`, falling back to `<given>.<surname>` on a collision.
- Seats follow department: Lantern Chat for nearly everyone, Crypt Docs for office departments, Belfry CRM for member
  facing departments, Ossuary Design for Marketing. A few part-time tellers hold no seat (Unlicensed user, `IO`).
- Some Living people appear with case, alias-domain or `+tag` variants in an export, to exercise the normaliser.
- Accounts are created at least seven days before the run, so nothing is pending.
- Boundary people with no finding: a person who left on 2026-11-04 with a disabled account, earlier leavers with
  disabled accounts, two future leavers who are Living, and a joiner starting 2026-11-16 with no account.
- The planted people of `planted.yaml` are written explicitly with their stories' dates, systems and seats. The
  Lantern Chat invoice is three seats above its assignments; every other invoice equals its assignments.
- `plant=False` (`--healthy`) writes the same company without the planted cases, with a seat for everyone and every
  invoice equal to its assignments.

## 9. Demo (Req 7.2)

`apps/ghosts/demo/build.py` runs `controls/staff-access.yaml` at 2026-11-04T02:00Z and 2026-11-05T02:00Z into
`runs/ghosts-demo`. Each run writes its review sheet (the control's downloads). Three decisions by "Dana
Okafor, IT manager", dated 2026-11-05, are imported into the second night through `ghosts.review` with a fixed clock,
so the first night shows no decision and the second shows three. The skeleton's `nightaudit.demo.export_run` writes
each night into `skeleton/web/public/demo/ghosts/<run id>/`; `scripts/build_demos.py` runs this build and lists
`ghosts-demo` (`base: "demo/ghosts/"`) in `apps.json`.

## 10. What the skeleton did not provide, and what it provides now

Ghosts was first built without write access to `skeleton/`. These were the gaps; skeleton Requirement 10 (design §18
of the three-way match) closed each one, and Ghosts no longer has any of the workarounds.

| Gap | Workaround at `ec92469` | Now |
|---|---|---|
| Connectors are not given the run time | `today` option, set to the run date | `HrRoster` reads `self.run_time` (skeleton Req 10.1); the control has no `today` |
| `RunResult` has no field for app notes | `seats.json` beside the run | `ghosts.seats:seat_notes` is a summariser; the notes are in the evidence chain, on the page and in the report (Req 10.2) |
| Enrichers are not given the control's directory or its alias domains | path resolved against `apps/ghosts/controls/`; alias table repeated and tested equal | `people_context(findings, options, control)` reads both from the control (Req 10.3) |
| The unkeyed money line's words are fixed in `report.py` | none possible | `ui.unkeyed`: "seats paid for nobody named" (Req 10.4) |
| Region templates have no `context` slots | the Left on column and the evidence show the date | each region's template states the condition from `{context:hr_status}` and other slots (Req 10.5) |
| No downloads, no decisions on the page | the sheet only on disk | `ui.downloads` links the review sheet; verified decisions show on the page (Req 10.6, 10.7) |

## 11. Correctness properties

Each property is one hypothesis test (100 examples, `derandomize` under CI), marked `@pytest.mark.property`, whose name
starts with `test_property_`.

### G1 — Intended membership follows the run date (validates Req 2.1, 2.2)

For any start date, optional leaving date and run date, `HrRoster` emits the person if and only if the start date is
on or before the run date and the leaving date is empty or after it.

### G2 — One person, one key (validates Req 1.1, 3.1)

For any local part, any change of case, any `+tag` and either the primary or the alias domain, the identity export
row and the HR row produce the same key, and a person with a seat lands in Living.

### G3 — Seats are conserved (validates Req 4.1, 4.2, 4.3)

For any number of assignments `a`, invoice quantity `q` and unit price, the connector emits `a` keyed records and
`max(0, q - a)` unkeyed records, each at the unit price, and the seat summary reports `max(0, q - a)` unnamed seats and
`max(0, a - q)` short seats.

### G4 — Hostile text changes no region (validates audit rule 4, Req 2.1, 3.1)

For any text placed in a person's name, title, department or display name, including instruction-like and markup
strings, every key's region equals the region with a benign string of the same length.

### G5 — A healthy company has zero findings (validates the product rule, Req 6.1)

For any seed, the healthy company (`plant=False`) produces zero findings, zero informational items, zero unkeyed rows
and zero pending keys.

### G6 — Same seed, same bytes (validates Req 6.2)

For any seed, `build_company(seed)` returns identical bytes on two calls, and for the committed seed it equals the
files in `apps/ghosts/data/`.

### G7 — Decisions only on reported findings (validates Req 5.2)

For any key that is not a finding of the run, an import naming it is refused, and `decisions.jsonl` is unchanged.

### G8 — Decision tampering is detected (validates Req 5.2)

For any decision chain that verifies, changing any single byte of `decisions.jsonl` makes `verify` fail.

### G9 — The review sheet shows values only as text (validates Req 5.1)

For any person, name or manager text, the HTML sheet contains it only in escaped form, and the CSV round trip returns
the original text while no cell starts with a formula character.

## 12. Acceptance

`apps/ghosts/planted.yaml` is the acceptance test. `python -m ghosts.acceptance` runs the Hollow Pines control at
2026-11-04T02:00Z and prints planted against found. The run passes only when:

- the non-informational findings equal the planted keys and regions, with nothing extra,
- the unkeyed billed rows are exactly three Lantern Chat seats at 8.00,
- at least one Unlicensed user (`IO`) exists,
- there are no pending keys and the run is complete,
- 180 people are in the intended ledger.

`planted.yaml` is read as written. The `noor.haddad` story is quoted in the file (commit `d7c668b`), so it parses.
